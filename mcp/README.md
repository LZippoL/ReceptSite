# MCP для Смаколика та Antigravity

Локальний Node.js сервер через stdio. Antigravity запускає процес автоматично. Окремий хостинг не потрібен. Сервер працює з тим самим Supabase, що й сайт: рецепти — `recipes`, статті — `articles`.

## Стан на цьому комп’ютері

Налаштовано 8 жовтня 2026 року: міграція застосована, адміністратор `lubcho224@gmail.com` має права редактора статей, функція `smakolyk-content` розгорнута. Локальний `.env` містить адресу шлюзу та випадковий токен агента. Ключ Supabase із повним доступом залишається в середовищі Edge Function і не копіюється на комп’ютер. У базі зберігається тільки SHA-256 хеш токена; анонімні й зареєстровані клієнти не можуть читати таблицю токенів.

Конфігурацію Antigravity вже доповнено й увімкнено. Оновіть MCP Servers або перезапустіть Antigravity, щоб він перечитав конфігурацію. Рецепти публікуються одразу; статті створюються як чернетки. Видалення заборонене також на шлюзі через `allow_delete=false`: зміна лише локального `MCP_ENABLE_DELETE` не надає такого права.

Перевірено реальний stdio MCP, читання бази, створення/редагування/читання тимчасової статті, очищення HTML, заборону публічного читання чернетки, відхилення неавторизованих запитів і видалення. Тестову чернетку прибрано. Вісім початкових статей сайту перенесено в Supabase зі збереженням ID і slug; вони доступні агенту для читання та редагування.

`edge-function/` містить розгорнутий код і закріплені npm-залежності. Після змін `src/repository.mjs` або `src/schemas.mjs` синхронізуйте їх із однойменними файлами в `edge-function/` та повторно розгорніть функцію. Платформна перевірка JWT вимкнена, оскільки функція перевіряє власний bearer-токен перед кожною дією.

Для відкликання токена встановіть `revoked=true` для відповідного запису `public.mcp_agent_tokens` через авторизований SQL-клієнт. Сам токен зберігається тільки у виключеному з Git файлі `mcp/.env`. Security Advisor може показувати інформаційне повідомлення про відсутність RLS-політик для таблиці токенів: тут це навмисна заборона доступу всім клієнтським ролям.

Налаштування шлюзу не змінює наявних публічних правил запису для `recipes` і `reviews`. Вони потребують окремого перегляду прав сайту.

## Підготовка для іншого комп’ютера або проєкту

1. Потрібен Node.js 22+. У папці `mcp` виконайте `npm ci` (залежності вже встановлені на цьому комп’ютері).
2. У Supabase SQL Editor виконайте `sql/001_articles.sql`. Він створює таблиці статей та редакторів, RLS-політики й унікальний індекс slug рецептів. Якщо в рецептах є дублікати slug, спершу усуньте їх: міграція транзакційна й відкотиться з помилкою. Для вже наявної таблиці `articles` з іншою структурою потрібне узгодження схеми; `create table if not exists` не змінює її стовпці.
3. Для редагування статей через вебадмінку додайте UUID вашого адміністратора з Authentication → Users:

   ```sql
   insert into public.content_editors (user_id)
   values ('UUID-ВАШОГО-АДМІНІСТРАТОРА')
   on conflict do nothing;
   ```

   Звичайні зареєстровані користувачі не отримують прав редактора. MCP-шлюз не потребує запису в `content_editors`.

4. Рекомендований режим: виконайте також `sql/002_agent_gateway.sql`, розгорніть `edge-function/` із власною bearer-автентифікацією, створіть випадковий 32-байтовий токен агента та збережіть лише його SHA-256 хеш у `mcp_agent_tokens`. У локальному `mcp/.env` задайте `MCP_GATEWAY_URL` і `MCP_AGENT_TOKEN`.

   Альтернативний прямий доступ: без `MCP_AGENT_TOKEN` задайте `SUPABASE_URL` та `SUPABASE_SECRET_KEY` із API Keys Supabase. Підтримується також legacy `SUPABASE_SERVICE_ROLE_KEY`. Публічний `sb_publishable_...` або `anon` ключ не підходить. Секрети зберігайте лише в локальному `.env`; не додавайте префікс `VITE_` і не надсилайте їх у чат. Сервер читає файл відносно свого шляху незалежно від робочої папки Antigravity.
5. Оновлення `src/services/articleService.ts` потрібно опублікувати для сайту та адмінки звичайним способом, щоб онлайн-версії читали спільну таблицю. Без цього MCP-рецепти будуть доступні поточному сайту, а MCP-статті — тільки оновленій версії сайту.

## Підключення Antigravity на цьому комп’ютері

Конфігурація: `antigravity.config.json`. Вона містить абсолютні шляхи для цього комп’ютера та увімкнений сервер (`disabled: false`).

На цьому комп’ютері запис `smakolyk-content` уже додано в `C:/Users/lubch/.gemini/config/mcp_config.json`. Для іншого комп’ютера додайте його в наявний `mcpServers`, зберігши інші сервери та скоригувавши абсолютні шляхи.

В Antigravity IDE: меню **… → MCP Servers → Manage MCP Servers → View raw config**, потім оновіть сервери. Шляхи й формат підтверджені [офіційною документацією Antigravity](https://antigravity.google/docs/mcp). У версіях із підтримкою локальної конфігурації також доступний `.agents/mcp_config.json`.

Не запускайте `npm start` окремо для роботи з Antigravity: stdio-процес має запускати сам клієнт.

## Інструменти

| Інструмент | Дія |
| --- | --- |
| `get_content_options` | Категорії, кухні, правила публікації |
| `list_recipes`, `list_articles` | Пошук за назвою та пагінація (`query`, `limit`, `offset`), короткі записи |
| `get_recipe`, `get_article` | Повний запис за `id` |
| `create_recipe` | Створення й негайна публікація рецепта |
| `create_article` | HTML-стаття, за замовчуванням чернетка |
| `update_recipe`, `update_article` | Редагування переданих полів; масиви замінюються повністю |
| `delete_recipe`, `delete_article` | Доступні лише якщо `MCP_ENABLE_DELETE=true`; потрібні `id` та точна поточна назва в `confirmTitle` |

Рецепти потребують назви, slug, опису, категорії, кухні, складності, часу підготовки й готування, порцій, калорій, БЖВ (`nutrition`), тегів, інгредієнтів, кроків і заповнених `seoTitle` та `seoDescription`. Автор за замовчуванням — «Смаколик». Агент заповнює всі ці поля, крім зображення. Для SEO-заголовка рекомендовано 50–60 символів, для SEO-опису — 140–160; порожні значення сервер відхиляє.

Підтримується JSON сайту з `id` інгредієнтів і `stepNumber`; без них сервер генерує значення сам. `totalTime` та дати обчислюються автоматично. Новий рецепт має `image: ""`, фото додається окремо в адмінці; при MCP-редагуванні наявне фото зберігається навіть якщо агент передасть інший URL. Сайт показує нейтральну заглушку, доки фото не додане. SEO-поля зберігаються в `recipes.seo_title` та `recipes.seo_description` і використовуються сторінкою рецепта. Для цього потрібні міграція `sql/003_recipe_seo.sql` (у поточному проєкті вже застосована) та оновлена збірка сайту й адмінки.

Рейтинги та кількість відгуків при редагуванні зберігаються. Початковий рейтинг нового рецепта — 0.

Статті потребують `slug`, `title`, `summary`, `content` (HTML), `image`, `category`, `readTime`, `author`. Публікація:

```json
{
  "id": "ID-СТАТТІ",
  "changes": { "status": "published" }
}
```

HTML статей очищується від скриптів, обробників подій і небезпечних посилань. Рецепти публікуються одразу; чернетки рецептів цим сервером не створюються. Статті-чернетки недоступні публічному клієнту завдяки RLS.

Сервер бачить тільки записи бази. Вісім початкових статей з `src/data/articles` уже імпортовано. Старі статті з localStorage залишаються видимими на сайті/в адмінці; для MCP-редагування їх потрібно перенести в базу. Збереження такої статті в оновленій адмінці переносить її в Supabase. Старі локальні записи не завантажуються автоматично. Видалення статей залишає позначку в базі, щоб початкова стаття не з’явилася знову.

Помилки запису в базу повертаються агенту явно. Сервер не повідомляє про успіх і не зберігає контент локально замість запису в Supabase. Читання на сайті зберігає резервний початковий/локальний контент у разі недоступності бази. Видалення рецептів постійне; для старих вбудованих рецептів існує попередня поведінка сайту з резервним каталогом при порожній/недоступній базі.

## Перевірка

```powershell
cd D:/antigravitypoj/siterecept/mcp
npm test
```

Тести перевіряють MCP handshake, справжній stdio-процес, список інструментів, валідацію, редагування без підміни інших полів, HTML, захист системних записів, підтвердження видалення та помилки бази. Вони не записують нічого у справжній Supabase. Перевірку реального з’єднання виконайте в Antigravity через `list_recipes` та `list_articles` після налаштування ключа й міграції.

Приклад запиту агенту:

> Через smakolyk-content створи рецепт українською з точними кількостями інгредієнтів і покроковими інструкціями. Потім створи пов’язану статтю як чернетку. Перед публікацією покажи мені статтю.
