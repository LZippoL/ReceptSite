# MCP для Смаколика та Antigravity

Локальний Node.js сервер через stdio. Antigravity запускає процес автоматично. Окремий хостинг не потрібен. Сервер працює з тим самим Supabase, що й сайт: рецепти — `recipes`, статті — `articles`.

## Підготовка

1. Потрібен Node.js 22+. У папці `mcp` виконайте `npm ci` (залежності вже встановлені на цьому комп’ютері).
2. У Supabase SQL Editor виконайте `sql/001_articles.sql`. Він створює таблиці статей та редакторів, RLS-політики й унікальний індекс slug рецептів. Якщо в рецептах є дублікати slug, спершу усуньте їх: міграція транзакційна й відкотиться з помилкою. Для вже наявної таблиці `articles` з іншою структурою потрібне узгодження схеми; `create table if not exists` не змінює її стовпці.
3. Для редагування статей через вебадмінку додайте UUID вашого адміністратора з Authentication → Users:

   ```sql
   insert into public.content_editors (user_id)
   values ('UUID-ВАШОГО-АДМІНІСТРАТОРА')
   on conflict do nothing;
   ```

   Звичайні зареєстровані користувачі не отримують прав редактора. MCP використовує серверний ключ і не потребує запису в `content_editors`.

4. Заповніть `mcp/.env` за прикладом `.env.example`: `SUPABASE_URL` та `SUPABASE_SECRET_KEY` із налаштувань API Keys вашого Supabase. Підтримується також legacy `SUPABASE_SERVICE_ROLE_KEY`. Публічний `sb_publishable_...` або `anon` ключ не підходить. Ключ зберігайте лише в локальному `.env`; не додавайте префікс `VITE_` і не надсилайте його в чат. Сервер читає файл відносно свого шляху незалежно від робочої папки Antigravity.
5. Оновлення `src/services/articleService.ts` потрібно опублікувати для сайту та адмінки звичайним способом, щоб онлайн-версії читали спільну таблицю. Без цього MCP-рецепти будуть доступні поточному сайту, а MCP-статті — тільки оновленій версії сайту.

## Підключення Antigravity на цьому комп’ютері

Конфігурація: `antigravity.config.json`. Вона містить абсолютні шляхи для цього комп’ютера та початково вимкнений сервер (`disabled: true`), доки не налаштована база.

Додайте запис `smakolyk-content` у наявний `mcpServers` файлу `C:/Users/lubch/.gemini/config/mcp_config.json`, зберігши інші сервери. Після підготовки змініть `disabled` на `false`.

В Antigravity IDE: меню **… → MCP Servers → Manage MCP Servers → View raw config**, потім оновіть сервери. Шляхи й формат підтверджені [офіційною документацією Antigravity](https://antigravity.google/docs/mcp). У версіях із підтримкою локальної конфігурації також доступний `.agents/mcp_config.json`.

Не запускайте `npm start` окремо для роботи з Antigravity: stdio-процес має запускати сам клієнт.

## Інструменти

| Інструмент | Дія |
| --- | --- |
| `get_content_options` | Категорії, кухні, правила публікації |
| `list_recipes`, `list_articles` | Пошук за назвою та пагінація (`query`, `limit`, `offset`), короткі записи |
| `get_recipe`, `get_article` | Повний запис за `id` |
| `create_recipe` | Створення й негайна публікація рецепта |
| `create_article` | HTML-стаття, за замовчуванням чернетка |
| `update_recipe`, `update_article` | Редагування переданих полів; масиви замінюються повністю |
| `delete_recipe`, `delete_article` | Доступні лише якщо `MCP_ENABLE_DELETE=true`; потрібні `id` та точна поточна назва в `confirmTitle` |

Рецепти потребують назви, slug, опису, фото, категорії, кухні, складності, часу підготовки й готування, порцій, калорій, автора, інгредієнтів і кроків. `totalTime`, ID інгредієнтів, номери кроків і дати генеруються сервером. Рейтинги та кількість відгуків при редагуванні зберігаються. Початковий рейтинг нового рецепта — 0.

Статті потребують `slug`, `title`, `summary`, `content` (HTML), `image`, `category`, `readTime`, `author`. Публікація:

```json
{
  "id": "ID-СТАТТІ",
  "changes": { "status": "published" }
}
```

HTML статей очищується від скриптів, обробників подій і небезпечних посилань. Рецепти публікуються одразу; чернетки рецептів цим сервером не створюються. Статті-чернетки недоступні публічному клієнту завдяки RLS.

Сервер бачить тільки записи бази. Початкові статті з `src/data/articles` і старі статті з localStorage залишаються видимими на сайті/в адмінці; для MCP-редагування їх потрібно перенести в базу. Збереження такої статті в оновленій адмінці переносить її в Supabase. Старі локальні записи не завантажуються автоматично. Видалення статей залишає позначку в базі, щоб початкова стаття не з’явилася знову.

Помилки запису в базу повертаються агенту явно. Сервер не повідомляє про успіх і не зберігає контент локально замість запису в Supabase. Читання на сайті зберігає резервний початковий/локальний контент у разі недоступності бази. Видалення рецептів постійне; для старих вбудованих рецептів існує попередня поведінка сайту з резервним каталогом при порожній/недоступній базі.

## Перевірка

```powershell
cd D:/antigravitypoj/siterecept/mcp
npm test
```

Тести перевіряють MCP handshake, справжній stdio-процес, список інструментів, валідацію, редагування без підміни інших полів, HTML, захист системних записів, підтвердження видалення та помилки бази. Вони не записують нічого у справжній Supabase. Перевірку реального з’єднання виконайте в Antigravity через `list_recipes` та `list_articles` після налаштування ключа й міграції.

Приклад запиту агенту:

> Через smakolyk-content створи рецепт українською з точними кількостями інгредієнтів і покроковими інструкціями. Потім створи пов’язану статтю як чернетку. Перед публікацією покажи мені статтю.
